# Выпуск автором
Автор: Arahort — arahort.pro, alex@arahort.pro.
## Состав публикации
Разработка приложения ведётся отдельно. В публичный GitHub попадают установщик, Dockerfile, Compose, хостовый обновлятор и документация; готовый пакет прикрепляется к GitHub Releases и входит в образ GHCR. Не добавляй `.private/`, исходные TypeScript/React, sourcemaps, `.env`, локальные аккаунты, OAuth-профиль, партии, uploads, логи, дампы и историю исходного проекта.
`app.tar.gz` должен содержать только папку `app/` с готовым приложением: `server/index.mjs`, `server/admin-cli.mjs`, `client/`, `prompts/`, `data/dnd-ru/`, production `package.json`, `package-lock.json`, `release.json`. У production package нет scripts и devDependencies. В `app/release.json` указываются `version` и `schemaVersion: 1`.
Серверный код внутри образа остаётся читаемым владельцем сервера; отсутствие репозитория исходников не гарантирует секретность реализации. Тексты сторонних лицензий сохраняются в licenses/ готового приложения.
## Первый выпуск
В рабочей авторской папке закрытые исходники находятся в .private/app. После изменений выполни из корня дистрибутива:
```sh
npm test
npm run release
```
Это две отдельные команды. Сборка проверяет TypeScript, создаёт минифицированные серверные и браузерные файлы без sourcemaps, выделяет production-зависимости, копирует лицензии и проверяет состав. Результат: artifacts/app.tar.gz для черновика GitHub Release и artifacts/dnd-ai-arahort-0.1.0-local.tar.gz для первого теста. Рядом лежат контрольные суммы SHA-256. .private/app и локальные артефакты исключены из Git; не удаляй закрытые исходники после публикации — они нужны автору для следующих патчей. Публичный клон устанавливается из готового образа и не восстанавливает закрытую среду сборки.
Авторские исходники имеют отдельную локальную Git-историю в .private/app; она не является частью публичного репозитория. После клонирования публичной части включи защиту коммитов командой git config core.hooksPath .githooks. Добавляй явные публичные файлы и проверяй staged-список: некоторые Git MCP обходят .gitignore при добавлении целой папки.
1. Создай отдельный публичный репозиторий GitHub и укажи его в release-source.json в поле repository. Это однократная настройка автора; конечный пользователь адрес не вводит. Пока репозиторий не создан, поле пустое и используется локальный режим --local.
2. Настрой GitHub Environment `release` и необходимые ограничения доступа к Actions. Workflow требует `contents:write` и `packages:write`.
3. Подготовь готовый `app.tar.gz` для версии `0.1.0`, создай черновик Release с тегом `v0.1.0` и прикрепи архив.
4. Запусти **Publish compiled release** с тегом `v0.1.0`. Ввод обрабатывается как данные; принимается только стабильная версия `vX.Y.Z`.
5. Workflow скачает архив, проверит пути, отсутствие исходников и совпадение версии, соберёт amd64 образ с AGY, опубликует GHCR, добавит release.json и dnd-ai-arahort.tar.gz. В установщик автоматически записывается проверенный адрес текущего репозитория GitHub через release-source.json.
6. Сделай GHCR package публичным. Проверь скачивание образа и установку без GitHub-авторизации на чистой тестовой машине. Протестируй Google-вход, ход, арт, Edge, приглашения, экспорт/импорт и копию.
7. Опубликуй проверенный черновик Release. Обновлятор использует только опубликованные стабильные Releases.
Workflow сам не переводит черновик в опубликованный выпуск. Не переиспользуй уже опубликованную версию для другого кода и не меняй её digest; исправление выпускай новым patch-тегом.
## Следующий патч
Подними версию скомпилированного приложения, оставив `schemaVersion=1` только при совместимой схеме. Создай новый черновик, прикрепи готовый пакет и повтори workflow. Manifest содержит полное имя образа с digest, `format:1`, `minimumUpdaterVersion:1` и `rollbackCompatible:true` для текущего формата. Изменение формата резервной копии/схемы требует изменения обновлятора и отдельной миграционной инструкции, а не одного переключения флага.
Перед публикацией проверь обновление предыдущей установки и принудительную ошибку запуска на её копии. Проверка одного HTTP health не доказывает работоспособность Gemini: нужен реальный ответ модели и игровой сценарий.
## Обновление AGY
Версия AGY закреплена в Dockerfile аргументами `AGY_VERSION`, `AGY_URL`, `AGY_SHA512`. Проверяй новый официальный manifest, обновляй все три значения вместе, проверяй авторизацию и формат stream-json. Не полагайся на `agy update` внутри работающего контейнера: его бинарник принадлежит root и обновляется новым образом приложения.
Официальные источники: [установка CLI](https://antigravity.google/docs/install?tab=cli), [manifest Linux amd64](https://antigravity-cli-auto-updater-974169037036.us-central1.run.app/manifests/linux_amd64.json), [Docker на Ubuntu](https://docs.docker.com/engine/install/ubuntu/).
