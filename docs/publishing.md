# Выпуск автором
Автор: Arahort — arahort.pro, alex@arahort.pro.
## Состав публикации
Разработка приложения ведётся отдельно. В публичный GitHub попадают установщик, Dockerfile, Compose, хостовый обновлятор и документация; готовый пакет прикрепляется к GitHub Releases и входит в образ GHCR. Не добавляй `.private/`, исходные TypeScript/React, sourcemaps, `.env`, локальные аккаунты, OAuth-профиль, партии, uploads, логи, дампы и историю исходного проекта.
`app.tar.gz` должен содержать только папку `app/` с готовым приложением: `server/index.mjs`, `server/admin-cli.mjs`, `client/`, `prompts/`, `data/dnd-ru/`, production `package.json`, `package-lock.json`, `release.json`. У production package нет scripts и devDependencies. В `app/release.json` указываются `version` и `schemaVersion: 1`.
Серверный код внутри образа остаётся читаемым владельцем сервера; отсутствие репозитория исходников не гарантирует секретность реализации. Тексты сторонних лицензий сохраняются в licenses/ готового приложения.
## Первый выпуск
В рабочей авторской папке закрытые исходники находятся в .private/app. После изменений выполни из корня дистрибутива:
```sh
npm test
npm run release
```
Это две отдельные команды. Сборка проверяет TypeScript, создаёт минифицированные серверные и браузерные файлы без sourcemaps, выделяет production-зависимости, копирует лицензии и проверяет состав. Результат: artifacts/app.tar.gz для черновика GitHub Release и artifacts/dnd-ai-arahort-<version>-local.tar.gz для первого теста; версия берётся из корневого package.json. Рядом лежат контрольные суммы SHA-256. .private/app и локальные артефакты исключены из Git; не удаляй закрытые исходники после публикации — они нужны автору для следующих патчей. Публичный клон устанавливается из готового образа и не восстанавливает закрытую среду сборки.
Авторские исходники имеют отдельную локальную Git-историю в .private/app; она не является частью публичного репозитория. После клонирования публичной части включи защиту коммитов командой git config core.hooksPath .githooks. Добавляй явные публичные файлы и проверяй staged-список: некоторые Git MCP обходят .gitignore при добавлении целой папки.
1. Создай отдельный публичный репозиторий GitHub и укажи его в release-source.json в поле repository. Это однократная настройка автора; конечный пользователь адрес не вводит. Пока репозиторий не создан, поле пустое и используется локальный режим --local.
2. Настрой GitHub Environment `release` и необходимые ограничения доступа к Actions. Workflow требует `contents:write` и `packages:write`.
3. Подними версию в корневом package.json, собери `app.tar.gz`, создай черновик Release с соответствующим тегом `vX.Y.Z` и прикрепи оба файла: `app.tar.gz` и `app.tar.gz.sha256`. Пример первого обновления установленной версии 0.1.0: тег `v0.1.1`. Коммит с установщиком и workflow должен уже находиться в репозитории.
4. Запусти **Publish compiled release** с выбранным тегом. Ввод обрабатывается как данные; принимается только стабильная версия `vX.Y.Z`. Выпуск должен оставаться черновиком: workflow откажется менять уже опубликованную версию.
5. Workflow скачает архив и контрольную сумму, проверит SHA-256, пути, отсутствие исходников и совпадение версии приложения/package.json, соберёт amd64 образ с AGY и опубликует GHCR. Образ получает OCI source/revision и версию без префикса v. В установщик автоматически записывается проверенный адрес текущего репозитория GitHub через release-source.json.
6. При первой публикации GHCR создаёт package с приватной видимостью. Workflow намеренно остановится, если образ нельзя скачать анонимно. В GitHub открой профиль автора → Packages → dnd-ai-arahort → Package settings → Change visibility → Public, затем повтори workflow для того же черновика. Проверка выполняется с пустым Docker config, скачивает образ по digest и сверяет версию внутри контейнера без сети. После успеха к черновику добавляются release.json, dnd-ai-arahort.tar.gz и его SHA-256. Проверь установку без GitHub-авторизации на чистой тестовой машине. Протестируй Google-вход, ход, арт, Edge, приглашения, экспорт/импорт и копию.
7. Опубликуй проверенный черновик Release. Обновлятор использует только опубликованные стабильные Releases.
Workflow сам не переводит черновик в опубликованный выпуск. Не переиспользуй уже опубликованную версию для другого кода и не меняй её digest; исправление выпускай новым patch-тегом.
Первичная видимость и связь контейнера с репозиторием описаны в [официальной документации GitHub Container registry](https://docs.github.com/en/packages/working-with-a-github-packages-registry/working-with-the-container-registry). Авторизация workflow не подтверждает, что установщик конечного пользователя скачает образ без учётной записи: для этого и нужна отдельная анонимная проверка.
## Следующий патч
Подними версию скомпилированного приложения, оставив `schemaVersion=1` только при совместимой схеме. Создай новый черновик, прикрепи готовый пакет и повтори workflow. Manifest содержит полное имя образа с digest, `format:1`, `minimumUpdaterVersion:1` и `rollbackCompatible:true` для текущего формата. Изменение формата резервной копии/схемы требует изменения обновлятора и отдельной миграционной инструкции, а не одного переключения флага.
Перед публикацией проверь обновление предыдущей установки и принудительную ошибку запуска на её копии. Проверка одного HTTP health не доказывает работоспособность Gemini: нужен реальный ответ модели и игровой сценарий.
## Обновление AGY
В Dockerfile аргументами `AGY_VERSION`, `AGY_URL`, `AGY_SHA512` закреплена только проверенная начальная копия. Начиная с 0.1.3 entrypoint от UID 1000 помещает её в постоянный `/home/dnd/.local/bin/agy`, если рабочего клиента ещё нет. Уже обновлённый клиент сохраняется при пересоздании контейнера. `/usr/local/bin/agy` — launcher, который применяет общие proxy/effort и выполняет native-клиент через Linux `execve`; корневые системные каталоги остаются недоступны для записи приложению.
Штатное автообновление AGY разрешено, в том числе при запуске через старые host ops. Проверяй авторизацию, формат stream-json и реальный ответ после смены версии клиента. Изменение начальной копии образа требует проверки официального manifest и одновременного обновления всех трёх аргументов. Публикация также выполняет Linux smoke без сети: writable-клиент, сохранение обновлённых байтов, `execve` с теми же PID/группой и proxy ON/OFF на фиктивном native-процессе.
Официальные источники: [установка CLI](https://antigravity.google/docs/install?tab=cli), [manifest Linux amd64](https://antigravity-cli-auto-updater-974169037036.us-central1.run.app/manifests/linux_amd64.json), [Docker на Ubuntu](https://docs.docker.com/engine/install/ubuntu/).
