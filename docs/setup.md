# Установка DND AI Arahort

Автор: **Arahort** — [arahort.pro](https://arahort.pro), alex@arahort.pro.

## 1. Подготовь сервер

Поддерживаются **Ubuntu Server 22.04, 24.04 и 26.04 LTS, x86_64**. Нужны SSH и пользователь с `sudo` либо root. Системный Python — 3.10.12 или новее с `tarfile.data_filter`; установщик проверяет это до изменений.

Для первого теста можно взять **1 vCPU и 2 ГБ RAM**: на такой машине проверены установка и обновление приложения, ход Мастера и Edge-озвучка. Это ориентир для теста, а не подтверждённый минимум для любой нагрузки. Одновременные партии, генерация изображений, история и резервные копии увеличивают потребление. Оставь свободное место для образов, данных и копий; GPU не нужен. PostgreSQL работает без pgvector и локальной модели эмбеддингов.

Установщик использует готовый образ приложения с Node.js 22 и Antigravity CLI 1.4.6, отдельный PostgreSQL 16 и Caddy для автоматического HTTPS. Исходники приложения, npm и ручная установка AGY на хосте не нужны. Docker Engine, Compose и Buildx устанавливаются из официального репозитория Docker, если Docker отсутствует. Существующий Docker проверяется без переустановки и перезапуска daemon; запущенные VPN-контейнеры установщик не останавливает.

Выбери способ доступа заранее:

- **Домен и автоматический HTTPS** — направь DNS A/AAAA на сервер, освободи TCP 80/443 и разреши входящие подключения к ним. Неверную AAAA-запись удали, если сервер не обслуживает IPv6.
- **IP или локальная сеть** — подготовь IPv4 сервера и свободный TCP-порт, например `8080`.
- **Существующий обратный прокси** — подготовь внешний URL и свободный локальный порт. HTTPS и WebSocket настраиваются на твоём nginx или другом прокси.

Установщик не меняет firewall и не останавливает существующие сайты. Для сервера в РФ подготовь HTTP(S) CONNECT прокси: адрес, порт, при необходимости логин и пароль.

## 2. Скачай готовый выпуск

Выполняй команды по очереди в одной SSH-сессии. Они создают новую временную папку для установочных файлов; постоянная установка будет находиться в `/opt/dnd-ai-arahort`.

Если `curl` отсутствует, установи его вместе с сертификатами и системным Python:

```sh
sudo apt-get update
sudo apt-get install -y ca-certificates curl python3
```

Проверь возможность безопасной распаковки:

```sh
python3 -c 'import sys,tarfile; print(sys.version); assert sys.version_info >= (3,10,12) and callable(getattr(tarfile,"data_filter",None)), "Обнови системный Python: нужен Python 3.10.12+ с tarfile.data_filter"; print("Python: OK")'
```

Скачай установщик и его контрольную сумму из [последнего выпуска](https://github.com/Arahort/dnd-ai-arahort/releases/latest):

```sh
DND_DOWNLOAD_DIR="$(mktemp -d -t dnd-ai-arahort-install.XXXXXX)"
cd "$DND_DOWNLOAD_DIR"
curl --fail --location --proto '=https' --output dnd-ai-arahort.tar.gz https://github.com/Arahort/dnd-ai-arahort/releases/latest/download/dnd-ai-arahort.tar.gz
curl --fail --location --proto '=https' --output dnd-ai-arahort.tar.gz.sha256 https://github.com/Arahort/dnd-ai-arahort/releases/latest/download/dnd-ai-arahort.tar.gz.sha256
sha256sum -c dnd-ai-arahort.tar.gz.sha256
```

Продолжай только после `dnd-ai-arahort.tar.gz: OK`. Если файл не скачался или сумма не совпала, скачай архив и сумму заново со страницы одного и того же выпуска.

Распакуй архив с безопасным фильтром в новую папку:

```sh
python3 -c 'import pathlib,tarfile; target=pathlib.Path("installer"); target.mkdir(); archive=tarfile.open("dnd-ai-arahort.tar.gz","r:gz"); archive.extractall(target,filter="data"); archive.close(); print("Установщик распакован в",target.resolve())'
sudo bash installer/install.sh
```

Адрес официального [репозитория Arahort/dnd-ai-arahort](https://github.com/Arahort/dnd-ai-arahort) уже встроен в выпуск. Выбирать репозиторий или вводить `owner/repository` не требуется.

## 3. Ответь на вопросы установщика

Сначала установщик спросит, находится ли сервер в РФ. Для РФ нужен прокси; для остальных серверов его можно указать по желанию или пропустить. Затем вводятся режим доступа и данные администратора.

**Прокси.** Протокол, хост/IP, порт, логин и пароль вводятся отдельно. Пароль скрыт, логин и пароль кодируются автоматически. Не нужно вставлять строку `http://user:pass@host` в команды. Настройка сохраняется в `.env` с правами `0600` и используется AGY внутри контейнера; БД и локальные адреса исключены через `NO_PROXY`.

Если Docker устанавливается впервые, установщик настраивает для него отдельный защищённый proxy drop-in `/etc/systemd/system/docker.service.d/dnd-ai-arahort-proxy.conf` и запускает новый daemon с ним. У существующего Docker proxy-настройки не меняются. Если он не может скачать образы GHCR/PostgreSQL/Caddy, обеспечь ему сетевой доступ через VPN, маршрут или настройку по [официальной инструкции Docker](https://docs.docker.com/engine/daemon/proxy/).

**Режим 1 — домен и автоматический HTTPS.** Введи домен без протокола и пути, например `game.example.org`, и контактный email для сертификата. Caddy занимает 80/443; UDP 443 используется для HTTP/3 и не обязателен для обычного HTTPS. При конфликте портов установщик предлагает внешний прокси. Приложение доступно через домен; порт `127.0.0.1:8080` в этом режиме не публикуется.

**Режим 2 — IP/локальная сеть по HTTP.** Введи IPv4 сервера и свободный порт. Например, сайт будет доступен по `http://192.168.1.10:8080`. Порт публикуется на всех IPv4-интерфейсах. Для доступа только из локальной сети ограничь его правилами firewall или маршрутизатора. Возможности браузера, требующие защищённого соединения, могут быть ограничены: микрофон обычно требует HTTPS или localhost.

**Режим 3 — существующий обратный прокси.** Укажи внешний URL и локальный порт. Приложение привязывается к `127.0.0.1`, а сертификат и внешний доступ обслуживает твой прокси. Пример nginx для уже настроенного HTTPS-сервера:

```nginx
location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_read_timeout 1200s;
}
```

Замени `8080` на выбранный порт. В этом режиме установщик не занимает 80/443. Для Caddy и внешнего прокси включается доверие к одному ближайшему прокси; в режиме прямого HTTP приложение не доверяет присланным клиентом `X-Forwarded-*`.

**Администратор.** Задай логин и дважды введи пароль. Подходит любой непустой пароль в пределах 256 символов; минимальная длина не навязывается. Пробелы и Unicode сохраняются, повторный ввод должен совпасть точно. Пароль не отображается и не записывается в `.env` или аргументы команды.

Дождись сообщения «Приложение отвечает» с адресом сайта. Установщик показывает этапы и вывод Docker; первая загрузка образов может занять время.

## 4. Активируй Gemini через SSH

В той же обычной SSH-сессии запусти:

```sh
sudo --preserve-env=SSH_CONNECTION,SSH_CLIENT,SSH_TTY dndctl login
```

Команда открывает AGY внутри контейнера с постоянным профилем приложения и указанным прокси. Рабочая папка `/data/work` доступна пользователю приложения для сохранения изображений и других результатов; права папки приложения `/app` не меняются. Начиная с 0.1.3 рабочий клиент находится в `/home/dnd/.local/bin/agy`, принадлежит UID 1000 и может штатно обновлять себя. Эта папка сохраняется в постоянном HOME; пересоздание контейнера не заменяет уже обновлённый клиент начальной версией образа. Переменные SSH помогают CLI выбрать удалённую авторизацию вместо запуска браузера на сервере.

1. Если вход ещё не выполнен, выбери личный Google-аккаунт.
2. Открой показанную ссылку на своём компьютере, войди в нужный аккаунт и подтверди доступ.
3. Верни одноразовый код в ожидающий запрос AGY в той же SSH-сессии и дождись подтверждения входа.
4. Выбери Gemini 3.8 Flash High и отправь короткое сообщение, например «Привет». Дождись настоящего ответа, затем заверши CLI сочетанием `Ctrl+C`.

Не выполняй отдельный вход в AGY от root на хосте: приложение использует свой HOME. Пароль Google не требуется установщику. Подсказки CLI и [официальная инструкция AGY](https://antigravity.google/docs/install?tab=cli) описывают процедуру входа.
## Настройки модели и прокси
В лобби администратор открывает шестерёнку «Управление таверной», затем вкладку «Модель и прокси». Здесь выбираются `low`, `medium` или `high`, включается HTTP(S) CONNECT прокси и задаются адрес, отдельный порт, логин и пароль. Для адреса без протокола используется HTTP; для HTTPS укажи `https://` перед именем сервера.
Пустое поле пароля сохраняет прежний пароль. Чтобы удалить его, используй отдельный флажок. Сохранённый пароль не возвращается в браузер. Настройки общие для приложения: новые ходы, арты, сводки, проверки лимитов и запуски через команду `agy` получают их без перезапуска контейнера. Уже запущенная задача завершает свои модельные этапы с прежними параметрами.
Включённый прокси передаётся клиенту и его штатному обновлятору; при выключении сохранённые параметры остаются в форме, но старые proxy-переменные окружения больше не применяются. Внутренние обращения CLI к localhost обходят прокси.
Конфигурация хранится в `/data/runtime/agy-settings.json` вне каталога загрузок сайта: каталог `0700`, файл `0600`. Она входит в защищённые резервные копии приложения вместе с остальными приватными настройками. Изменения через панель временно блокируются на время обслуживания.

Авторизация, список моделей и `/usage` сами по себе не подтверждают генерацию. Ошибки квоты, доступности модели или `503 No capacity` оценивай по реальному ответу и журналу AGY. При сетевой ошибке не удаляй профиль: сначала проверь соединение и лог.

AGY запускается с `--dangerously-skip-permissions`: все инструменты разрешены без подтверждения, списки `permissions.deny` и `permissions.ask` очищены. Установщик задаёт `toolPermission=always-proceed`, `allowNonWorkspaceAccess=true`, `enableTerminalSandbox=false`, `artifactReviewPolicy=always-proceed` и `agentMode=accept-edits`. В серверном профиле список `trustedWorkspaces` содержит только рабочую папку `/data/work`; доступ инструментов за её пределами разрешён настройкой `allowNonWorkspaceAccess`. Перед изменением существующего `settings.json` рядом сохраняется копия `settings.json.backup-*` с правами `0600`; авторизация, модель и остальные настройки сохраняются. Возможность генерации изображений проверяется отдельным реальным арт-запросом. [Настройки CLI](https://antigravity.google/docs/settings?tab=cli), [правила инструментов](https://antigravity.google/docs/permissions?tab=cli).

## 5. Пригласи игроков и проверь партию

Открой адрес, показанный установщиком, и войди созданным администратором. В панели администратора создай одноразовые инвайт-коды: каждый игрок регистрируется со своим кодом. Свободной регистрации нет.

Кнопка **«Проверить лимиты»** показывает сведения AGY `/usage`: группы моделей, остаток недельного и пятичасового лимита, время сброса. Проверка не запускает генерацию и не заменяет тестовый ход.

Создай тестовую партию, дождись ответа Мастера, запроси арт и озвучь новое сообщение через Edge TTS. Проверь сохранение партии после повторного входа. Для переноса своих партий и пользователей используй [инструкцию по импорту и экспорту](migration.md): совпадающий точный логин связывается с существующим аккаунтом без изменения его пароля и прав; отсутствующий создаётся с прежним паролем.

Версию и состояние обновлятора можно посмотреть по SSH:

```sh
sudo dndctl status
```

Эта команда показывает состояние установки и обновлений, а работоспособность Gemini подтверждается ответом в партии.

## 6. Выбери effort модели

По умолчанию всё приложение использует **Gemini 3.8 Flash, high**. Допустимы `low`, `medium` и `high`. Настройка общая для Мастера, вспомогательных запросов и генерации артов.

Для переключения на medium:

```sh
sudo dndctl effort medium
```

Команда дождётся завершения запросов, создаст резервную копию и пересоздаст только контейнер приложения. Для возврата:

```sh
sudo dndctl effort high
```

Вручную редактировать `.env` не требуется. Варианты модели могут отличаться по времени ответа, расходу лимитов и доступности; проверяй выбранный вариант на своей партии.

## 7. Обновляй и сохраняй данные

Администратор может проверить и установить новый выпуск кнопками в приложении. По SSH доступны:

```sh
sudo dndctl check
sudo dndctl update
sudo dndctl status
```

Обновление сохраняет партии, файлы, учётные записи и профиль Google. Перед заменой приложения служба завершает активные задания и создаёт резервную копию. Подробности: [обновления, резервные копии и восстановление](updates.md).

Файлы установки находятся в `/opt/dnd-ai-arahort`, постоянные данные — в `/var/lib/dnd-ai-arahort`. Удаление контейнера приложения не удаляет данные. Профиль AGY и резервные копии содержат закрытые сведения; не публикуй их.

Повторный запуск установщика не перезаписывает готовую установку. Если установка прервалась, продолжи из папки распакованного выпуска:

```sh
sudo bash installer/install.sh --resume
```

Если ты уже находишься внутри папки `installer`, используй `sudo bash install.sh --resume`. Для обычного обновления установленного приложения используй панель администратора или `dndctl update`.
