# Установка и сеть
Автор: Arahort — arahort.pro, alex@arahort.pro.
## Что устанавливается
Поддерживаются Ubuntu Server 22.04 (Jammy), 24.04 (Noble) и 26.04 (Resolute) LTS на x86_64. При установке нового Docker выбирается официальный apt-репозиторий соответствующего выпуска. Существующий Docker проверяется без переустановки, перезапуска daemon и изменения его proxy-настроек.
- Docker Engine, Compose и Buildx из репозитория Docker, если Docker отсутствует. Существующий Docker не переустанавливается; должны работать daemon и Compose plugin.
- Приложение на Node.js 22 и закреплённая Antigravity CLI 1.4.6 внутри образа. Бинарник AGY загружается из официального хранилища Google и проверяется SHA-512, полученным из официального manifest. AGY не является npm-пакетом этого приложения.
- PostgreSQL 16 без vector extension и Caddy для режима автоматического HTTPS.
- Хостовая служба `dnd-ai-arahort-updater.service`, команда `dndctl`, защищённый Unix socket для обновлений.
Адрес официальных выпусков встроен автором в release-source.json. Установщик получает его автоматически; вводить GitHub-репозиторий не нужно. Локальная сборка с пустым адресом работает без удалённых обновлений.
Пакеты PostgreSQL/Node.js не устанавливаются прямо в ОС. Удаление контейнера приложения не удаляет партии, файлы и Google-профиль.
Минимальная длина пароля не навязывается: можно выбрать любой непустой пароль. Это правило одинаково для администратора в установщике, регистрации по приглашению, смены пароля и административного сброса. При повторном вводе проверяется точное совпадение; пробелы внутри пароля сохраняются.
Во время сборки и запуска контейнеров установщик показывает текущий этап и поток Docker без ожидания завершения всей операции.
## Домен с автоматическим HTTPS
Укажи домен без протокола и пути, например `game.example.org`, и контактный email. DNS должен вести на этот сервер. Входящие TCP 80/443 должны быть доступны для сертификата; UDP 443 используется Caddy для HTTP/3 и не обязателен для обычного HTTPS. Неверную AAAA-запись удаляй у DNS-провайдера, если сервер не обслуживает IPv6.
Установщик проверяет занятость 80/443 и предлагает режим внешнего прокси при конфликте. Он не останавливает существующие сайты, не правит их nginx-конфигурацию и не меняет firewall.
## IP или локальная сеть
Укажи IPv4 и свободный порт, например `192.168.1.10:8080`. Приложение публикуется по HTTP на всех IPv4-интерфейсах. Для доступа только из локальной сети ограничь порт правилами firewall или маршрутизатора. Если сервер имеет внешний адрес, режим также работает напрямую по IP. Браузерные возможности, которым требуется secure context, могут быть ограничены при HTTP; микрофон обычно требует HTTPS или localhost.
## Существующий nginx или другой прокси
Выбери режим 3, внешний URL и свободный локальный порт. Пример nginx для уже настроенного HTTPS-сервера:
```nginx
location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_read_timeout 1200s;
}
```
SSL-сертификат и настройки server-блока остаются за владельцем сервера. Для этого режима установщик не занимает 80/443.
В режиме прямого HTTP приложение не доверяет `X-Forwarded-*` от клиентов. Для Caddy и существующего прокси установщик включает доверие к одному ближайшему прокси через `DND_TRUST_PROXY=1`; локальный порт внешнего прокси привязан к `127.0.0.1`.
## Прокси и активация AGY
Параметры HTTP(S) CONNECT прокси вводятся отдельно: протокол, хост/IP, порт, логин, скрытый пароль. Логин и пароль URL-кодируются; не нужно вручную вставлять `http://user:pass@host` в shell history. Прокси сохраняется в `.env` с правами `0600`, передаётся контейнеру приложения и применяется к запуску AGY. БД и localhost исключены через `NO_PROXY`.
Если Docker устанавливается этим запуском, установщик создаёт отдельный защищённый proxy drop-in `/etc/systemd/system/docker.service.d/dnd-ai-arahort-proxy.conf` для скачивания образов и перезапускает только этот новый daemon. У уже существующего Docker настройки не меняются. Если существующий daemon не может скачать GHCR/PostgreSQL/Caddy, владелец должен обеспечить ему доступ: VPN, разрешённый сетевой маршрут или прокси по официальной [инструкции Docker](https://docs.docker.com/engine/daemon/proxy/). Для `--local` proxy также передаётся сборке через стандартные Docker build args без значения в командной строке; в Dockerfile эти ARG не объявлены, чтобы учётные данные не попадали в history образа.
Вход Google выполняется `sudo --preserve-env=SSH_CONNECTION,SSH_CLIENT,SSH_TTY dndctl login`. Не выполняй вход от root на хосте: у приложения отдельный постоянный HOME. Не удаляй профиль для диагностики сетевых ошибок. Сначала проверь ответ AGY и его лог. `503 No capacity` означает отказ конкретного запроса у сервиса, но не доказывает, что все варианты модели недоступны.
Установщик добавляет недостающие защитные настройки AGY: `request-review`, запрет shell-команд, MCP и чтения URL инструментами модели. Существующая авторизация и остальные настройки сохраняются. Игровые запросы работают из отдельной временной папки; пароли БД и секрет обновлятора не передаются дочернему AGY. Возможность штатной генерации изображений в этом режиме проверяй реальным арт-запросом. [Настройки CLI](https://antigravity.google/docs/settings?tab=cli), [правила инструментов](https://antigravity.google/docs/permissions?tab=cli).
Если меняешь Google-аккаунт, заверши вход через интерфейс AGY внутри этого же контейнера. Ни установщик, ни автор проекта не получают Google-пароль.
## Проверка после установки
1. `sudo dndctl status` показывает установленную версию. Статус обновлятора не подтверждает доступность Gemini.
2. Открой сайт, войди администратором, создай приглашение и зарегистрируй игрока отдельным браузерным профилем.
3. Выполни настоящий ход, получи ответ Мастера, запроси арт и новую Edge-озвучку.
4. Перезапусти только контейнер приложения и проверь сохранение партии и входа Google.
5. Проверь экспорт/импорт тестовой партии и восстановление копии на отдельной тестовой установке.
Предел одновременных партий и минимальный VPS определяются этим прогоном с замером CPU, RAM, swap и диска. Сборка образа у автора и запуск готового образа у пользователя имеют разные требования.
