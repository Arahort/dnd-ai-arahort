# DND AI Arahort
Самостоятельная серверная версия игры с AI Мастером. Автор: **Arahort**, [arahort.pro](https://arahort.pro), alex@arahort.pro. Некоммерческое использование — на условиях [LICENSE](LICENSE).
Мастер и арты работают через Antigravity CLI и собственный Google-аккаунт владельца сервера. По умолчанию — **Gemini 3.8 Flash, high**. Озвучка — Edge TTS: «Дмитрий», скорость +5%, высота −15 Гц по умолчанию. Долговременная память использует русский полнотекстовый поиск PostgreSQL: GPU, pgvector и локальная модель эмбеддингов не нужны.
## Установка
Первый выпуск рассчитан на чистую **Ubuntu Server 24.04 LTS, x86_64**, SSH и пользователя с `sudo`. Для тестового запуска разумно начать с 2 ГБ RAM и измерить потребление своей партии. Это ориентир для проверки, а не подтверждённый минимум. Потребление зависит от параллельных AGY-процессов, артов, истории и резервных копий; GPU не нужен.
Скачай архив **dnd-ai-arahort.tar.gz** из опубликованного GitHub Release этого проекта, распакуй в отдельную папку и запусти из неё:
```sh
sudo bash install.sh
```
Установщик последовательно спросит:
1. Сервер в РФ или нет. Для РФ потребуется HTTP(S) CONNECT прокси; пароль вводится скрыто. За пределами РФ прокси можно пропустить.
2. Режим доступа: домен с автоматическим HTTPS, IP/локальная сеть по HTTP или существующий обратный прокси.
3. Публичный GitHub-репозиторий автора в формате `owner/repository` для получения готовых выпусков.
4. Логин и пароль администратора. Пароль не попадает в командную строку и `.env`.
Docker Engine и Compose при необходимости устанавливаются из официального apt-репозитория Docker. Приложение и AGY запускаются в готовом образе, PostgreSQL 16 — отдельным контейнером. Порт БД наружу не публикуется. Исходники приложения для установки не нужны.
Файлы установки находятся в `/opt/dnd-ai-arahort`, постоянные данные — в `/var/lib/dnd-ai-arahort`. Существующую установку повторный запуск не перезаписывает. Если установка прервалась, используй `sudo bash install.sh --resume` из исходного архива; скомпилированный локальный пакет продолжай с `--local --resume`.
Для режима домена заранее направь DNS A/AAAA на сервер и открой TCP 80/443. Если на этих портах уже работает nginx/Caddy, выбери существующий обратный прокси: приложение слушает только `127.0.0.1` на выбранном порту. [Подробная настройка](docs/setup.md).
## Активация Gemini
После установки выполни по SSH:
```sh
sudo --preserve-env=SSH_CONNECTION,SSH_CLIENT,SSH_TTY dndctl login
```
Команда сохраняет признаки SSH и передаёт их в контейнер: AGY должен выбрать удалённый вход вместо локального браузера. Профиль и указанный при установке прокси принадлежат пользователю приложения.
1. В терминале AGY выбери вход через личный Google-аккаунт.
2. Скопируй выданный URL авторизации и открой его в браузере своего компьютера.
3. Войди в нужный аккаунт и подтверди доступ. Браузер покажет одноразовый код.
4. Вставь код в ожидающий запрос AGY в той же SSH-сессии и дождись подтверждения входа.
Не вводи пароль Google в установщик приложения и не публикуй URL/код авторизации. Процедура описана в [официальной инструкции AGY](https://antigravity.google/docs/install?tab=cli).
После входа выбери Gemini 3.8 Flash High и отправь короткое сообщение. Реальный ответ подтверждает генерацию. Успешная авторизация, `/usage` и доступный список моделей сами по себе её не подтверждают. Ограничения Google-аккаунта, доступность модели и ошибки `503 No capacity` зависят от сервиса Google.
Профиль AGY сохраняется в отдельной постоянной папке и переживает обновление образа. Не публикуй эту папку и резервные копии.
## Игроки и партии
Открой сайт и войди созданным администратором. Регистрация доступна только по одноразовому приглашению, которое создаёт администратор. Кнопка «Проверить лимиты» показывает данные встроенной команды AGY /usage: группы моделей, точный остаток недельного и пятичасового лимита и время сброса. Проверка не запускает генерацию. Администратор управляет обновлениями. Экспорт и импорт партий используют собственный формат этой редакции; старые архивы исходного проекта не поддерживаются.
## Effort модели
Допустимы только `low`, `medium`, `high`; по умолчанию `high`. Изменение применяется ко всему приложению, включая Мастера, вспомогательные запросы и арты:
```sh
sudo dndctl effort medium
```
Команда дождётся завершения запросов, создаст резервную копию и пересоздаст контейнер приложения. Для возврата используй `sudo dndctl effort high`. Файл `.env` вручную редактировать не требуется.
## Обновления
В разделе администратора нажми проверку обновлений, прочитай сведения о выпуске и подтверди установку выбранной версии. Автоматической установки без подтверждения нет. Через SSH доступны `sudo dndctl check`, `sudo dndctl update` и `sudo dndctl status`.
Обновление выполняет отдельная служба хоста: приложение не получает Docker socket. Служба принимает только проверку состояния, проверку выпусков и установку явно выбранного выпуска из заданного публичного репозитория. Образ закреплён digest; произвольный URL или shell-команда через админку не принимаются.
Сначала скачивается образ, затем блокируются новые изменения, завершаются текущие задания, создаётся резервная копия БД, файлов, OAuth-профиля и конфигурации. После запуска проверяется HTTP health. До завершения проверки запись закрыта. При ошибке до открытия записи восстанавливается прежний образ вместе с копией данных; если восстановление не удалось, запись остаётся закрытой для ручной диагностики. Сбой после попытки открыть запись требует проверки новой версии и сохраняет уже принятые изменения. [Обновления, резервные копии и восстановление](docs/updates.md).
## Сборка и выпуск автором
Публичный репозиторий содержит установку и документацию; скомпилированное приложение распространяется в GitHub Releases и GHCR. TypeScript/React исходники разработки остаются отдельно и в публикацию не входят. Владельцу сервера доступны серверный JavaScript и браузерные файлы внутри образа; отсутствие исходников не означает защиту от изучения реализации.
Для теста готового пакета с папкой `app/`:
```sh
sudo bash install.sh --local
```
Для выпуска автор подготавливает `app.tar.gz`, прикрепляет его к черновику GitHub Release и запускает **Publish compiled release**. Workflow проверяет состав пакета, собирает Linux amd64 образ, публикует его в GHCR и добавляет установщик с `release.json`. Черновик публикует автор после проверки; настрой пакет GHCR как **public**. [Порядок выпуска](docs/publishing.md).
